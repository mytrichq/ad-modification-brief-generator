# Ad Modification Brief Generator

Внутрішній інструмент креативної команди SockLock. Бере сценарій рекламного ролика, який уже добре продає (переможця), і за кілька хвилин робить з нього пакет перевірених нових версій (модифікацій) разом із брифом для motion-дизайнера.

**Проблема, яку закриває.** Щоб витрачати на рекламу $800k на місяць замість $400k, потрібно ~500 модифікацій замість ~240. Дизайнери вже працюють по 200 год на місяць при нормі ~165 і «половину дня» витрачають на ручне переписування хуків, перших фраз і тексту на екрані. Інструмент забирає цю частину роботи: дизайнер отримує готовий бриф «що саме змінити» і одразу монтує.

🎬 **Демо-відео (2:17):** [дивитись на Google Drive](https://drive.google.com/file/d/1gAHL2zVKvHHDTobFEFT5jSFlp6D5xGX3/view?usp=sharing)

```
скрипт переможця ─► сцени* ─► DNA ─► модифікації ─► QA ─► рев'ю ─► brief (PDF / MD / CSV)
(текст, Google Doc,           що     N цілісних      бренд,  approve /     │
 .docx/.txt/.md/.csv,         keep,  скриптів        офер,   reject +      │
 бібліотека)                  що     різних типів    дублі   причина       │
                              test                                         ▼
                rules.md + examples/  ◄── автоматичне навчання ◄── feedback.jsonl
* вільний текст LLM розбиває на сцени, людина перевіряє. Схвалена модифікація може стати новим оригіналом.
```

## Швидкий старт

Потрібен лише **Node.js ≥ 20**. Встановлювати нічого не треба: npm-залежностей немає.

```bash
git clone https://github.com/mytrichq/ad-modification-brief-generator.git && cd ad-modification-brief-generator

node cli/ad-mod-brief.js demo      # увесь цикл на записаних відповідях LLM, без ключів
node cli/ad-mod-brief.js ui        # веб-інтерфейс → http://localhost:4321
```

Для реальної генерації підійде будь-що з цього (вибирається автоматично в такому порядку):

| Провайдер | Що потрібно | Примітка |
|---|---|---|
| `anthropic` | `ANTHROPIC_API_KEY` | Messages API зі structured outputs, модель `claude-opus-5-5` (змінюється через `ANTHROPIC_MODEL`) |
| `openai` | `OPENAI_API_KEY` | Chat Completions з `json_schema`, модель `gpt-5` (змінюється через `OPENAI_MODEL`) |
| `claude-code` | встановлений [Claude Code](https://claude.com/claude-code) | Без ключа: `claude -p --json-schema` під твоїм логіном |
| `demo` | нічого | Записані відповіді для прикладу C014 |

Примусово: `--provider <name>`. Для PDF потрібен Chrome/Chromium (шлях можна задати через `CHROME_PATH`). Без нього буде HTML, який друкується в PDF з браузера.

## Три способи працювати

**1. CLI**
```bash
node cli/ad-mod-brief.js generate --script brief.docx       # скрипт → DNA → пакет модифікацій → QA (за замовчуванням 10, --n змінює)
node cli/ad-mod-brief.js generate --doc https://docs.google.com/document/d/…
pbpaste | node cli/ad-mod-brief.js generate --script -      # з буфера обміну
node cli/ad-mod-brief.js generate --from C014-AI01          # схвалена модифікація як новий оригінал
node cli/ad-mod-brief.js generate C014 --n 6 --types hook,recut
node cli/ad-mod-brief.js fixes                # підказані виправлення оригіналу; fix <n> apply|keep
node cli/ad-mod-brief.js review               # approve / reject з причиною; правила оновлюються самі
node cli/ad-mod-brief.js export --format pdf  # brief для дизайнерів
node cli/ad-mod-brief.js stats                # метрики пілоту
node cli/ad-mod-brief.js rank                 # опційно: переможці з Meta-експорту за EGP
```
Усі команди підтримують `--json`, тож поверх них можна зібрати власний UI. `--help` показує повний список.

**2. Веб-інтерфейс** (`ui`), п'ять кроків:
- **Script:** вставити текст, дати посилання на Google Doc, завантажити файл, взяти скрипт з бібліотеки або спробувати приклад.
- **Keep or test:** «чому працює», підказані виправлення рядків, які виходять за факти бренду (застосувати чи лишити оригінал), і для кожної сцени чи клітинки вибір: лишити слово в слово чи можна міняти.
- **Generating:** генерація пакета (через Claude Code зазвичай 2–3 хв).
- **Review:** по одній модифікації: обсяг роботи (Light / Medium / Heavy), гіпотеза, «було → стало», зауваження перевірок. Клавіші `J` / `K` — рух, `A` / `R` — approve / reject, `U` — скасувати.
- **Brief:** hook stack і решта схвалених модифікацій, PDF, Markdown, CSV.

Окремі сторінки: **Library** (скрипти, схвалені модифікації, приклади), **Team rules** (свої правила і вивчені з рев'ю), **Find winners** (ранжування Meta-експорту).

**3. Claude Code skill.** Відкрий репозиторій у Claude Code і напиши, наприклад, «зроби модифікації для C014». Skill (`skill/`, підключений у `.claude/skills/`) веде той самий процес, тільки генерує сам Claude у сесії. `SKILL.md` описує кроки, `references/` — типи модифікацій, правила написання, як вести рев'ю і команди CLI, `examples/` — реальні схвалені й відхилені варіанти з причинами і приклад брифу. Claude читає їх тоді, коли доходить до відповідного кроку. CLI при цьому видає точні промпти (`prompt`), валідує відповіді (`ingest`), робить QA і веде пам'ять.

## Вхідні дані

**Скрипт переможця** — єдиний обов'язковий вхід. Підходить будь-який з п'яти варіантів:

| Джерело | Як |
|---|---|
| Текст | Вставити як є: таблиця сцен або звичайний текст (тоді LLM розбиває на сцени, людина перевіряє) |
| Google Doc | Посилання на документ з доступом «Anyone with the link». Таблиці з документа зберігаються |
| Файл | `.docx` (таблиця Word або абзаци), `.txt`, `.md`, `.csv`. Колонки розпізнаються за синонімами: `VO`, `Caption`, `Shot`, `Timing` тощо |
| Бібліотека | Попередні скрипти та **схвалені модифікації**. Модифікація, яка виграла, стає новим оригіналом: це наступна гілка дерева креативу |
| Meta-експорт *(опційно)* | «Find winners»: CSV з Ads Manager → переможці за EGP → їхній скрипт |

Приклади лежать у `data/scripts/`: таблиця (`C014.md`), вільний текст (`C031.txt`), документ Word (`C022-brief.docx`).

**`data/brand.json`**: єдині факти про продукт і офер, які дозволено стверджувати, заборонені твердження, тон, ліміти довжини.

**Meta-експорт (опційно, для «Find winners» / `rank`).** Ads Manager → Ads → період → Export table data → CSV. Обов'язкові лише три колонки: назва реклами, витрати, покупки. Назви колонок можуть бути інші (`Cost`, `Spend`, `Results`, `Conversions` тощо), тож підійде й вивантаження з Google Sheets чи Triple Whale. Рядок з підсумками пропускається. Якщо колонки немає, інструмент пише, якої саме. ROMI рахується як в аналітика: `purchases × LTV $68 / spend`. На цифрах дата-руму (CPA $50) це дає 136%. Демо-експорт `data/ads.csv` синтетичний: `data/generate-ads.js`, відкалібрований під воронку з кейсу.

## Як влаштовано

- **Creative DNA.** LLM пояснює, чому переможець працює, і позначає кожну клітинку таблиці як `lock` (доведене ядро: механіка, демо, офер) або `open` (те, що варто тестувати). Модифікація змінює лише відкрите, тому ризик невеликий: ідея вже перевірена. Якщо в оригіналі є рядок, що виходить за факти бренду, інструмент лише **підказує виправлення**: ролик уже крутиться в рекламі, тож його текст змінюється тільки після явного «Apply», а бриф позначає такі рядки як «Differs from the live ad».
- **Модифікації відповідають реальним важелям продакшну**, від дешевих до дорогих:
  - `hook`: нове відкриття на тому самому тілі ролика; кілька хуків монтуються за один сеанс («hook stack»);
  - `recut`: інший порядок, темп чи тривалість лише з наявного футажу;
  - `revoice`: інший голос, темп, музика, стиль субтитрів;
  - `ending`: новий фінал і CTA;
  - `new_angle`: інша больова історія на тій самій механіці й офері;
  - `new_creator`: ту саму історію розповідає інша людина (новий UGC-автор).

  Кожна модифікація є цілісним скриптом і має:
  - план футажу по сценах: `reuse` / `trim` / `new`;
  - direction: хто в кадрі, локація, голос, музика, субтитри;
  - гіпотезу «If we…, then…, because…» і метрику, за якою читати тест (hook rate, CTR, CPA, completion).

  З футажу детерміновано рахується обсяг роботи: **Light** (лише текстові шари), **Medium** (нова озвучка чи перемонтаж) або **Heavy** (нова зйомка). Дешеві модифікації закривають обсяг, а «важкі» дають Meta нові, не схожі на попередні оголошення.
- **QA детермінований, без LLM** (`core/check.js`). Галюцинація, яка дійшла до Meta, коштує грошей, тому перевірки мають бути передбачуваними:
  заборонені твердження (медичні, гарантії, неіснуючі умови оферу, конкуренти) · ціна та кількість пар лише як в офері · locked-клітинки не змінені · обсяг змін відповідає типу (хук чіпає лише відкриття, кінцівка лише фінал, а новий кут і новий автор змінюють більшість відкритих сцен, інакше це не нове оголошення) · ліміти довжини тексту на екрані й хука · CTA веде на квіз · майже-дублікати всередині пакета (trigram Jaccard ≥ 0.6). Дублікати не косметика: Meta групує майже однакові креативи, і такий креатив не купує нового охоплення.
- **Пам'ять команди: просто файли в `workspace/`.**
  `feedback.jsonl` (кожен approve/reject з причиною) → `rules.md` (дві частини: правила, які команда пише сама і які навчання не змінює, та до 15 правил, вивчених з рев'ю; усі додаються в кожен промпт) + `examples/` (схвалені модифікації стають прикладами в промпті: приклади працюють краще за правила). **Навчання автоматичне.** Після завершеного рев'ю правила оновлюються у фоні, а перед кожною генерацією інструмент дочитує відгуки, яких ще немає в правилах. Окремої кнопки «навчити» немає. Закомітив `workspace/`, і досвід одного маркетолога стає досвідом усієї команди, а git зберігає історію правил.
- **Один промпт на всі входи.** `core/prompts.js` + `core/prompts/*.md` + `core/schemas/*.json` однакові для API, Claude Code, skill і UI.

## Вартість

Реальні прогони через Claude Code (Opus 5.5), по 10 модифікацій з планом футажу й direction: **≈ $0,41–0,48 за пакет за цінами Claude API, тобто ≈ $0,045 за модифікацію**, і 2–3,5 хв від скрипту до пакета. 500 модифікацій на місяць коштуватимуть **≈ $22/міс** на токени через API. Через Claude Code на підписці окремої оплати немає, генерація йде в межах лімітів підписки. Інфраструктури немає. Для порівняння, найкраща готова зв'язка (Atria + Foreplay) коштує ≈ $630–870/міс і не покриває ключове: зміни лише вибраних клітинок сцени, перевірку тверджень про продукт, контроль дублікатів і навчання на нашому фідбеку.

## Як міряємо успіх

Пілот на 2 тижні з 2 із 6 дизайнерів (решта працює як раніше, це контрольна група):

| Метрика | Зараз | Ціль | Звідки |
|---|---|---|---|
| Час дизайнера на модифікацію | ~3 год | ≤ 2,25 год (−25%) | тайм-трекінг пілотної та контрольної груп |
| Acceptance rate (схвалено / переглянуто) | — | ≥ 50% | `stats` |
| Частка модифікацій пілотних дизайнерів, зроблених через інструмент (adoption) | — | ≥ 80% | `stats` + трекер продакшну |
| Модифікацій на місяць без найму | 240 | 320 за 1–2 міс | трекер продакшну |
| ROMI модифікацій з інструмента | 140% (зроблені вручну) | не нижче, ніж у зроблених вручну | Meta-експорт, `parent_id` у назві |
| Порушення guardrails, що дійшли до Meta | — | 0 | QA + рев'ю |

**Kill-критерій:** якщо після 2 тижнів економія менша за 15 хв на модифікацію або acceptance rate нижчий за 30%, зупиняємось і переглядаємо підхід.

## Наступна ітерація

1. **Відео на вході.** Розпізнавання мови (speech-to-text) і ключові кадри дають таблицю сцен автоматично. Тоді можна брати переможців, у яких немає скрипту, і навіть конкурентів з Meta Ads Library.
2. **Зворотний зв'язок з результатами.** Імпорт Meta-експорту по згенерованих модифікаціях (`parent_id` вже в назві) показуватиме, які типи модифікацій і які правила реально піднімають ROMI, а не лише проходять рев'ю.
3. **Експорт у data-driven шаблони After Effects** (JSON/CSV з текстом по сценах). Для модифікацій типу `hook` і `ending` це скоротить і сам монтаж, а не лише підготовку.
4. **Локалізація** (параметр `market`): той самий двигун і guardrails для DE/FR, щоб розблокувати тести, які стоять 2 місяці.
5. **Спільне сховище** (Airtable/S3) замість git, коли з'являться доступи до інфраструктури.

## Структура

```
core/      ядро: пайплайн, перевірки, експорт, пам'ять, LLM-провайдери; core/prompts/ і core/schemas/
cli/       CLI: ad-mod-brief.js (вхід), args.js, print.js, help.js; commands/ за кроками: winners, generate, review, export, skill, demo
ui/        веб-інтерфейс: server.js (локальний сервер) + index.html
skill/     Claude Code skill: SKILL.md, references/, examples/; підключений через .claude/skills/ad-mod-brief
data/      brand.json, ads.csv (+ генератор), scripts/ (приклади), demo/ (записані відповіді для demo)
workspace/ пам'ять команди: rules.md, feedback.jsonl, examples/ (runs/ у .gitignore)
test/      npm test
```

CLI, UI і skill не залежать одне від одного: усі три викликають одне й те саме ядро з `core/`.

**Обмеження MVP.** Дані синтетичні. Demo показує записані відповіді, а не живу генерацію. QA перевіряє текст, а не готове відео. Інструмент не монтує відео, а готує завдання для дизайнера.
